# Read-your-writes via append position plus wait-for-checkpoint

Store.Append (and thus Repository.Save) reports the GlobalSeq of the last event it stored; an edge that wants read-your-writes on the service's own views captures that position through a context collector (eventstore.CapturePosition — the Command interface and every handler stay untouched) and blocks on projection.WaitForCheckpoint until the projection's store checkpoint passes it, bounded by the context deadline (on timeout the edge still answers 202 honestly). No dual write: the position comes from the append that already happened, and the wait only reads checkpoints — projections stay async and idempotent. Poll-based first (cheap point reads at 25ms); Postgres LISTEN/NOTIFY is a later optimization behind the same function. Rejected returning the position from Dispatch/Save signatures (ripples through every handler for a concern only edges have) and synchronous projection application (breaks the async model). Cross-service read-your-writes is out of scope: a foreign store's write position is not comparable with the local inbox checkpoint.
